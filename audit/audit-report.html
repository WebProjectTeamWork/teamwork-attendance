Verdict

The core security design is sound: Argon2 passwords, HMAC-hashed attendance codes, pinned JWT algorithm, ownership checks on every professor endpoint, HttpOnly cookie sessions, magic-byte upload checks, and a DOM built with textContent. The main risks are deployment configuration (committed secrets and the professor access code in docker-compose.yml), missing HTTP security headers, and sign-in and attendance throttling that lets one user lock out others. No code-execution or injection issue was found.

Findings

High  S-01 Committed secrets and professor access code in Compose

docker-compose.yml commits JWT_SECRET (line 20), CODE_SECRET (21), PROFESSOR_SIGNUP_CODE (24) and a database password (7), and publishes port 8000 on all interfaces (29). APP_ENV is not set, so the production guard in main.py:96 never runs.

Impact: anyone who can read the repo and reach a deployment from this file can register as a professor, forge JWTs and forge QR tokens.

Fix: move secrets out of the committed file; set APP_ENV=production outside local use; bind to 127.0.0.1; rotate values if ever used with real data.

Medium  S-02 No HTTP security headers; CDN script without integrity

Live check: /health and / send no CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy or HSTS. index.html:13 loads a script from cdnjs with no SRI hash.

Impact: the app can be framed (clickjacking on professor actions) and has no CSP backstop.

Fix: header middleware with frame-ancestors 'none'; SRI or self-host the script.

Medium  S-03 Logout does not invalidate the token

Live check: a Bearer token copied before logout still returned 200 afterwards. Logout only clears the cookie (main.py:320-321); the token lives 30 minutes.

Fix: server-side denylist or a "tokens valid after" timestamp checked in current_user.

Medium  S-04 Account-wide sign-in lockout enables targeted denial of service

Failures are counted per email only (main.py:271-291). Live check: after 10 wrong passwords the correct password returns 429 for 15 minutes. Anyone who knows an email can lock that user out.

Fix: key the throttle on email plus IP, or add backoff.

Medium  S-05 Shared-IP limit can block a whole class

The attendance limit is 30 failures per IP per 10 minutes, and it is checked before the code (main.py:516 vs 530). Students on one campus NAT share an IP, so a few mistyped codes can block classmates who type the correct one. The device limit is bypassable because X-Device-Id comes from the client.

Fix: do not let the IP limit gate correct codes; use backoff instead of a hard IP block.

Medium  D-01 Roster import merges students with the same name

placeholder_email() (roster.py:84-89) builds the account email from the name. Two students with the same name become one account, and the second enrollment is silently skipped (roster.py:144-149). That student cannot be marked present, so class statistics are wrong.

Fix: key on the department's student ID, or stop and report duplicate names.

Low  S-06 to S-12 Hardening

S-06 Account enumeration: duplicate email returns 409 (main.py:257); enrollment returns 404 for unknown emails (main.py:359-360); login skips the hash for unknown users (main.py:286, timing, not measured).
S-07 No maximum password length (schemas.py:13); a 4,096-character password was accepted.
S-08 Cookie Secure depends on the request scheme (main.py:313); CSRF defence relies only on SameSite=Strict (main.py:314).
S-09 External attachment URLs accepted and rendered as links (schemas.py:188, app.js:1735): a phishing path around the upload checks.
S-10 PDFs served inline from the app origin (main.py:801-807); mitigated by the magic-byte check, nosniff and no-store.
S-11 Docker image runs as root with no HEALTHCHECK (Dockerfile).
S-12 /docs and /openapi.json are public (verified 200).

Low  Correctness, quality and operations

C-01 Session date uses UTC (main.py:426) while notifications use Europe/Bucharest; sessions opened after midnight local time get the previous date.
C-02 Concurrent duplicate registration returns 500 (main.py:256-268 has no IntegrityError handler).
Q-01 main.py is 1,232 lines and 48 functions; split by feature.
Q-02 Complexity over 10: confirm_attendance 13, match_names 12, create_vote 11.
Q-03 Ownership checks repeated inline (main.py:459, 478, 618) although owned_session() exists.
Q-04 Lint debt: unused imports (main.py:3, 11; two test files), zip() without strict=, name shadowing at main.py:885.
Q-05 No migrations; schema from create_all() plus an additive helper (db.py:27).
Q-06 N+1 queries in list_sections (main.py:955-1004); unbounded message loads in thread_summaries (newsletter.py:307).
Q-07 No frontend tests (about 3,275 lines of JS).
Ops-01 Dockerfile runs pip install ., ignoring uv.lock, so builds are not reproducible.

Recommended order

  1. S-01: remove committed secrets, set APP_ENV=production, bind to localhost.
  2. S-04 and S-05: stop one user's failures from blocking others.
  3. S-02, S-03, S-12: security headers, logout revocation, hide API docs in production.
  4. D-01: roster homonym merge.
  5. C-01, C-02, S-06, S-07, S-09: smaller correctness and hardening items.
  6. Q-01 to Q-07 and Ops-01: refactoring, migrations, frontend tests, pinned dependencies.

Method

Read all backend modules and the security-relevant frontend paths. Ran the existing test suite with coverage, Bandit, Ruff, pip-audit and node --check. Enumerated routes by AST. Ran 10 in-process probes. Not covered: network scanning, load testing, Docker build, browser testing, timing measurement. Raw evidence is in audit/evidence/.
